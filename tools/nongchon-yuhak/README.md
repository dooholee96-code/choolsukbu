# 전북 농어촌유학생 명단 정리 도구

도교육청 농어촌유학 담당 업무용. 한 시트에 쌓여 있던 유학생 명단 원데이터를
정규화한 관리용 엑셀 워크북으로 바꾼다.

```bash
pip install openpyxl
python build_workbook.py <원본.xlsx> <출력.xlsx>
```

원본 워크북의 **1번 시트만** 읽는다. 숨김 시트(연도별 명단, 정보공개 등)는
과거 산출물이라 건드리지 않는다.

## 왜 나눴나

원본은 1행이 '한 번의 신청'인데, 그 안에 세 가지가 섞여 있었다.

| 섞여 있던 것 | 예 |
|---|---|
| 사람에 관한 정보 | 성명, 성별, 보호자, 원 소속교 |
| 그 회차의 심사 결과 | 배정 희망서, 참가 신청서, 최종 배정, 미선정 사유 |
| 여러 해에 걸친 유학 이력 | 유학 학년도 `2024, 2025, 2026`, 시작일, 종료일 |

세 번째가 한 칸에 뭉쳐 있어서 "2025학년도 1학기 몇 명"을 세려면 학년도 칸을
검색하고 접수일로 2학기를 손으로 빼내야 했다. 그래서 셋을 따로 뗐다.

- `학생마스터` — 1행 = 학생
- `신청이력` — 1행 = 원본 1행 (모집 차수별 신청 건). 원본 열을 모두 보존한다
- `유학이력` — 1행 = 학생 × 학기. 집계는 전부 이 표를 센다

## 학기를 어떻게 펼치나

3월 1일 시작이 1학기, 9월 1일 시작이 2학기, 학년도는 3월에 바뀐다.
신청 건의 시작일과 종료일 사이에 걸치는 학기를 모두 만든다.

검산은 원본이 해 준다. 이렇게 펼친 학년도 집합이 원본 '유학 학년도' 칸과
**507건 전부 일치** (유학 학년도가 적혀 있는 배정 건 전부)했고, 학기별 인원도 원본 메모에 적힌 공식 수치와 맞았다.

| | 계산값 | 원본에 적혀 있던 값 |
|---|---|---|
| 2022학년도 | 27 | 27 |
| 2023학년도 | 85 | 85 (메모: "최종 85명이 맞음") |
| 2024학년도 | 165 | 165 (메모: "최종 165명 맞음") |
| 2025학년도 1학기 | 204 | 204 |

학년도 인원은 `1학기 인원 + 2학기 신규`로 센다. 2학기의 '계속'은 이미 1학기에
세어졌기 때문이다.

## 판단이 필요했던 곳

**배정 판정.** `최종배정` 칸이 비어 있는 행이 100건 가까이 된다. 아래 순서로 본다.

1. `최종배정`이 `배정`/`최종배정` → 배정
2. `최종배정`이 `X`/`미배정`이거나 사유가 적혀 있으면 → 미배정
3. 비어 있으면 `종료일` 칸을 본다. 날짜나 `현재`가 있으면 → 배정
   (`종료일` 칸에 `최종배정`이라고 잘못 적힌 행 7건도 여기서 걸린다)
4. 그래도 안 되면 `배정 희망서`가 `선정` → **확인필요**, 다른 사유 → 미배정

`확인필요`로 남은 건은 `데이터검증` 시트에 모아 둔다. 사람이 봐야 하는 것을
조용히 한쪽으로 정하지 않기 위해서다.

**거주 유형.** `홈스테이형(2022)→유학센터형(2023)` 같은 값은 학기별로 갈라
2022학년도 행은 홈스테이형, 2023학년도부터는 유학센터형으로 넣는다.

**학년.** 각 학기의 학년은 전입 당시 학년에서 학년도가 바뀐 횟수만큼 올린다.
계산 결과가 원본 '현재 학년'과 다르면 검증 항목으로 남긴다.

**체제비 3년.** 도청 지원은 최대 3년 = 6학기. 시작 학기부터 여섯 번째 학기의
마지막 날이 만료일이다. 원본 메모의 "2023년 3월 시작 → 2026년 2월까지"와 같다.
단가는 워크북의 `설정_지원단가` 시트에 빼 두었다 (2025. 전북 농촌유학 시행 지침 기준).

## 개인정보

원본과 산출물 모두 학생·보호자 이름과 연락처를 담고 있다. **저장소에 커밋하지 않는다.**
스크립트만 버전 관리하고, 워크북은 담당자 PC에 둔다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `transform.py` | 원본 1번 시트 → 학생/신청/유학이력/검증 자료구조 |
| `build_workbook.py` | 그 자료구조 → 서식·수식이 들어간 엑셀 워크북 |
