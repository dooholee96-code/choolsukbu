# 출석부 (choolsukbu)

학원·공부방용 **오프라인 출결 관리 앱**. 서버 없이 기기 안 SQLite에만 저장한다.

원생마다 정규 수업 요일과 시간대를 등록해 두면, 앱이 오늘 와야 하는 학생만 골라 보여준다. 체크인 시점에 등원 유형을 자동으로 판정한다.

| 조건 | 기록되는 상태 |
|---|---|
| 오늘 명단에 있고 시간대 안 (시작 60분 전 ~ 끝) | `scheduled` (정상 출석) |
| 오늘 명단에 있지만 그보다 일찍, 또는 끝난 뒤 | `unexpected` (예외) |
| 오늘 명단에 없는 날 | `unexpected` (예외) |

'오늘 명단'은 정규 시간표에 그 날짜의 [일정 예외](#일정-예외)를 얹은 결과다. 휴강·특강·요일 변경이 여기서 반영된다.
시작 전 유예(`EARLY_ARRIVAL_GRACE_MINUTES`, `utils/roster`)를 두는 이유: 학교 끝나고 바로 오는 아이들이라 20~40분 일찍 도착하는 것이 보통이다. 시작 시각부터만 정상으로 보면 예외 칸이 정상 등원으로 가득 차서 진짜 예외가 묻힌다.
수업 시간은 [요일마다 다르게](#요일별-수업-시간) 둘 수 있다.

**대상 기기**: iPhone(세로 고정), iPad Pro 13"(전방향, Stage Manager·Split View 지원)

---

## 요구사항

- Node.js 20 이상
- iPad에 설치하려면 **macOS + Xcode**
- 무료 Apple ID로 충분하다 — [기기 간 동기화](#기기-간-동기화)만 유료 개발자 계정이 필요하다

## 개발 중 실행

```bash
npm install

npm start        # Expo Go로 실행 (QR 스캔)
npm run web      # 브라우저에서 실행. 반응형 확인이 가장 빠르다
npm run typecheck
npm test
```

`npm run web`으로 열고 창 너비를 조절하면 1→2→3열 전환을 바로 볼 수 있다.

> Expo Go에서는 **iPad 화면 방향 설정이 적용되지 않는다.** `ios.infoPlist`는 빌드 시점에 Info.plist로 들어가는데 Expo Go는 자체 Info.plist를 쓰기 때문이다. 방향 동작을 확인하려면 아래 네이티브 빌드가 필요하다.

### 테스트

`node --test`를 `tsx`로 돌린다. 러너를 따로 두지 않은 이유는, 검증이 필요한 곳이
**React를 거치지 않는 순수 로직**이기 때문이다 — 병합 규칙, 요일별 시간, 명단 계산,
PIN 해싱. 화면은 브라우저에서 직접 만져 보는 편이 빠르다.

| 파일 | 무엇을 |
|---|---|
| `tests/merge.test.mts` | 두 기기 기록을 합치는 규칙 |
| `tests/apply.test.mts` | 병합 결과를 쓰는 SQL — `node:sqlite`에 실제로 돌린다 |
| `tests/schedule.test.mts` | 요일별 수업 시간, 명단, 지각 표시 |
| `tests/lock.test.mts` | PIN 해싱 규칙 |
| `tests/backup.test.mts` | 전체 백업과 복원 |
| `tests/migration.test.mts` | 옛 버전 데이터베이스 올리기 |

`tests/helpers/db.mts`가 `expo-sqlite` 표면을 `node:sqlite` 위에 얹는다. 병합 SQL과
마이그레이션은 가장 조용히 틀릴 수 있는 부분이라 실제 데이터베이스에 돌려봐야 한다.
마이그레이션 검증은 **원생 3명과 출결 120건이 든 v1 데이터베이스**를 만들어 v4까지
올린 뒤 하나도 빠지지 않았는지 센다.

`src/db`와 `utils/id.ts`가 네이티브 모듈을 함수 안에서 부르는 것도 이 때문이다.
최상단에서 부르면 스키마와 마이그레이션이 React Native에 묶여, 옛 버전 데이터베이스를
만들어 올려보는 길이 막힌다.

## iPad에 설치하기

Mac에 iPad를 케이블로 연결하고:

```bash
npx expo run:ios --device --configuration Release
```

연결된 기기 목록이 뜨면 iPad를 고른다.

`--configuration Release`가 중요하다. JS 번들이 앱 안에 포함되어 **개발 서버 없이 독립 실행**된다. 이걸 빼면 Mac이 꺼져 있을 때 앱이 뜨지 않는다.

### 최초 1회만 필요한 설정

**서명 팀 선택** — 빌드가 코드 서명에서 멈추면 `ios/app.xcworkspace`를 Xcode로 열고 `app` 타깃 → Signing & Capabilities → Team에서 본인 Apple ID를 고른다. 계정이 없으면 Xcode → Settings → Accounts에서 Apple ID를 추가한다.

**iPad에서 개발자 신뢰** — 설치 후 처음 실행할 때 "신뢰하지 않은 개발자" 경고가 뜬다. iPad에서 설정 → 일반 → VPN 및 기기 관리 → 본인 Apple ID → 신뢰.

### 7일마다 재설치

무료 Apple ID는 서명 유효기간이 **7일**이다. 만료되면 앱은 홈 화면에 남아 있지만 실행되지 않는다. 같은 명령을 다시 돌리면 된다.

```bash
npx expo run:ios --device --configuration Release
```

**데이터는 지워지지 않는다.** 같은 번들 ID로 덮어쓰는 업그레이드 설치라 SQLite 파일이 그대로 유지된다. 단, 앱을 손으로 삭제하면 데이터도 함께 사라진다.

### 켜자마자 꺼지면 — 부품 버전이 어긋난 것이다

SDK 57이 만드는 iOS 프로젝트는 Expo 모듈을 소스로 빌드하지 않고, 각 npm 패키지에 들어 있는
**미리 컴파일된 파일**을 쓴다 (Podfile의 `EXPO_USE_PRECOMPILED_MODULES`). 그 파일은 패키지를
올린 시점의 `expo-modules-core`에 맞춰 만들어져서, 버전이 서로 어긋나면 **빌드는 멀쩡히 끝나는데
앱이 켜지자마자 꺼진다.** 충돌 기록에는 `Symbol not found: ...ExpoModulesCore...`가 찍힌다.

실제로 그랬다. `expo` 57.0.4가 끌어온 `expo-modules-core` 57.0.3과 `expo-file-system` 57.0.2는
npm에 올라간 조합 자체가 맞지 않았다 — 파일시스템이 찾는 `willDestroy`가 코어에 없었다.
SDK 57의 최신 패치 세트(`expo` 57.0.26, 코어 57.0.20)로 함께 올려 맞췄다.

의존성을 올렸으면 아이패드에 올리기 전에 한 번 돌린다. 각 모듈이 코어에서 가져다 쓰는 기호가
전부 코어에 있는지 대조한다 — 앱을 켤 때 iOS가 하는 일과 같다.

```bash
npm run check:native
```

Expo 패키지는 **같은 SDK의 최신 패치로 함께** 올린다(`npx expo install --fix`). 하나만 올리면
이 대조가 깨진다.

서명 팀은 `app.json`의 `ios.appleTeamId`에 적혀 있다. 그래서 `npx expo prebuild --clean`으로
`ios` 폴더를 새로 만들어도 Xcode에서 팀을 다시 고를 필요가 없다. 팀 ID는 비밀값이 아니다 —
서명된 모든 앱에 그대로 들어 있다.

네이티브 모듈이 늘어난 뒤의 첫 빌드(예: `expo-haptics`)는 `Running pod install in the ios directory`가 찍히며 몇 분 더 걸린다. `expo run:ios`가 `package.json`의 의존성이 바뀐 것을 보고 알아서 돌리는 것이라 따로 할 일은 없다. `ios` 폴더를 새로 만들어도(`prebuild --clean`) 서명 팀은 `app.json`에서 다시 들어간다.

무료 계정에는 기기당 앱 3개, 주당 App ID 10개 제한도 있다.

## 설정 바꾸기

`app.json`이 유일한 소스다. `app.config.js`는 그 위에 iCloud 플러그인만 조건부로 얹는다. `ios/`와 `android/`는 `expo prebuild`가 만드는 산출물이라 커밋하지 않는다.

| 값 | 위치 | 비고 |
|---|---|---|
| 홈 화면 이름 | `expo.name` | 현재 `출석부` |
| 번들 ID | `expo.ios.bundleIdentifier` | 현재 `com.dooholee96.choolsukbu`. App Store 제출 전까지는 자유롭게 변경 가능 |
| 화면 방향 | `expo.ios.infoPlist` | iPhone 세로 / iPad 전방향으로 분기 |

`app.json`을 고친 뒤에는 `npx expo prebuild --clean`으로 네이티브 프로젝트를 다시 만든다.

## 숲속 테마

크림 배경에 호수 블루를 얹은 파스텔 팔레트. `Screen` 뒤에 `ForestBackground`가
깔린다. 배경은 폰 화면(390x844) 기준으로 그려서 `xMidYMax slice`로 채우므로,
넓은 창에서는 3.5배까지 확대된다. 그래서 compact가 아닌 사이즈 클래스에서는
불투명도를 낮춰 카드보다 뒤로 물러나게 한다.

호숫가에는 토끼 세 마리가 산다 — 언덕을 오가며 깡충 뛰는 살구 토끼, 제자리에서 뛰는
흰 토끼, 가끔 뒤돌아보는 보라 토끼, 그리고 호수의 파문.

- 토끼는 네이티브 드라이버(UI 스레드)로 움직인다. 파문만 JS 드라이버다.
- 넓은 창(iPad)에서는 토끼만 60%로 줄인다 (`RABBIT_SCALE_WIDE`). 언덕·호수와 토끼가 서는 자리는 장면 배율 그대로라 발은 언덕에 붙어 있다.
- **보이는 탭의 토끼만 움직인다.** 네 탭이 저마다 배경을 들고 있어서, 다 돌리면 안 보이는 파문까지 매 프레임 JS를 깨운다.
- 크기는 창이 아니라 배경이 실제로 깔린 자리(`onLayout`)로 잡는다. 탭 화면은 탭바만큼 짧아서, 창 크기로 놓으면 토끼가 언덕에서 뜬다.
- '동작 줄이기'가 켜져 있으면 모두 멈춘다.
- 웹 미리보기에서는 애니메이션이 도는 동안 `document.fonts`가 'loading'에 머물러 Playwright의 `page.screenshot()`이 글꼴을 기다리다 멈춘다. 화면은 60fps로 멀쩡하다. 스크린샷은 CDP `Page.captureScreenshot`으로 찍거나 `reducedMotion: 'reduce'`로 띄운다.

### 색은 두 벌이다

| 용도 | 토큰 |
|---|---|
| 면·틴트 배경 | `primary` `secondary` `success` `danger` |
| 그 위에 얹히는 글씨·아이콘 | `primaryStrong` `secondaryStrong` `successStrong` `dangerStrong` |

파스텔 원색 위의 흰 글씨는 WCAG AA(4.5:1)에 크게 못 미친다 — 측정값으로
primary 2.46:1, secondary 1.90:1, success 2.10:1이었다. `Strong` 계열은 색조를
유지한 채 명도만 낮춰 기준을 맞춘 값이다.
**버튼 배경, 상태 태그 글씨, 아바타 이니셜, 탭바 활성 색에는 반드시 `Strong` 쪽을 쓴다.**

`Strong` 값을 다시 잡을 때는 세 조건을 모두 봐야 한다. 순백 기준으로만 계산하면
카드(`#FFFDFB`)와 배경(`#F6F2EC`)이 완전한 흰색이 아니라 4.4대로 내려가 미달한다.

| 쓰이는 자리 | 대비 기준 |
|---|---|
| 버튼 배경 | 그 위 흰 글씨 |
| 카드 위 글씨 | `cardBackground` |
| 배경 위 글씨 (탭바) | `background` — 가장 어두워 여기가 병목 |

`textSecondary`도 시안값 `#9B8AA3`(배경 위 2.87:1)에서 `#776A7E`로 낮췄다.
시간·학년·날짜처럼 실제로 읽어야 하는 정보에 쓰이는 색이라 기준을 맞췄다.

현재 팔레트는 위 12개 조합 전부 4.5:1 이상이다.

### 글꼴

고운돋움(본문) / 고운바탕 Bold(강조). `App.tsx`에서 `useFonts`로 읽고 DB 초기화와
같은 게이트에서 기다린다. styled 템플릿에는 `font-weight` 대신
`font-family: ${({ theme }) => theme.fonts.bold}`를 쓴다 — 커스텀 폰트에
`font-weight`를 주면 합성 볼드로 뭉개진다.

로딩이 실패하면 `systemFontTheme`으로 갈아끼운다. 존재하지 않는 글꼴 이름이
`font-family`에 남으면 네이티브에서 글자가 그려지지 않기 때문이다.

### 반응형 규칙

기기 종류가 아니라 **현재 창 폭**으로 판정한다. iPad는 Stage Manager와 Split View에서 창 크기가 임의로 바뀌기 때문이다.

| 폭 | 사이즈 클래스 | 열 |
|---|---|---|
| < 700pt | compact | 1 |
| 700–1099pt | medium | 2 |
| ≥ 1100pt | expanded | 3 |

**오늘 화면은 넓은 창에서 보드가 된다.** 목록을 한 줄로 내려 쓰면 아이패드 Pro에서도 등원 예정 몇 명만 보이고, 누가 와 있는지 보려면 스크롤해야 했다. 넓은 창에서는 칸을 옆으로 늘어놓고, 칸마다 따로 스크롤한다.

| 창 | 오늘 화면 |
|---|---|
| compact | 예전 목록 (큰 요약 카드 + 한 줄 카드) |
| medium (iPad 세로) | 두 칸 — **등원 예정** / **수업 중** (그 아래 하원·결석) |
| expanded (iPad 가로) | 세 칸 — **등원 예정** / **수업 중** / **하원 · 결석** |

- 칸마다 서로 먼 색을 하나씩 쓴다 — 등원 예정은 해 노랑, 수업 중은 풀빛 초록('출석' 표시와 같은 색), 하원은 호수 블루, 결석은 빨강 묶음. 원색은 옅은 바탕·윗변 띠·아이콘·요약 띠의 점에만 쓰고, 제목 글씨는 본문 색, 숫자 뱃지는 진한 색 위 흰 글씨다 (원색 위 글씨는 대비가 모자란다). 칸 안의 묶음(결석, 좁은 보드의 하원)은 반투명이 아니라 불투명하게 섞은 색이다 — 초록 칸 위의 옅은 빨강은 갈색으로 탁해진다. 좁은 화면의 목록도 무리 제목 앞 점으로 같은 색을 잇는다.
- 보드의 카드는 납작한 모양(`StudentCard`의 `dense`)이다. 상태 표시를 이름 옆에, 버튼을 옆으로 늘어놓아 높이를 절반 가까이 줄였다.
- 등원 예정은 **수업 시작 시각순**(같으면 이름순). 다음에 올 아이가 위에 온다. 40명 명단을 이름순으로 두면 4시 반 아이를 매번 훑어 찾아야 한다.
- 수업 중 칸은 먼저 온 순서다. 대개 먼저 온 아이가 먼저 가므로 하원을 누를 카드가 위에 모인다. 하원 칸은 방금 간 아이가 위라 잘못 눌렀으면 바로 보인다.
- 요약은 한 줄 띠로 줄였다 (등원 수, 수업 중·하원·결석·남음). 금액은 여기서도 다루지 않는다.
- medium의 폭 제한은 1100pt다. 900에서 자르면 iPad Pro 13" 세로(1032pt)에서 보드 양옆에 빈 띠가 남는다.

### 주의사항

`styled-components` 템플릿 안에서 `//` 주석을 쓰면 안 된다. 네이티브 파서는 블록 주석만 제거하기 때문에, `//` 뒤의 값 파싱이 다음 `:`까지 이어지면서 **바로 다음 선언 한 줄을 통째로 삼킨다.** 주석이 필요하면 템플릿 밖에 `/* */`로 쓴다.

`Alert`를 직접 쓰지 말고 `utils/dialog`의 `confirm`·`notify`를 쓴다. `react-native-web`의 `Alert.alert`는 `static alert() {}` 인 빈 스텁이라, 웹에서는 확인 대화상자로 감싼 동작이 아무 반응 없이 사라진다.

`ScrollView`에는 반드시 `style={{ flex: 1 }}`을 준다. React Native의 기본 `flexShrink`는 웹과 달리 0이라, flex를 주지 않으면 ScrollView가 부모를 넘어 **내용 높이만큼 커진다.** 그러면 스크롤 영역이 화면보다 커져서 스크롤이 먹지 않고 내용이 잘린다. `react-native-web`은 `overflow: auto`로 그리기 때문에 웹에서는 멀쩡해 보인다 — 실기기에서만 드러난다.

모달은 크기와 상관없이 `presentation: 'modal'`로 띄운다. iPad에서는 가운데 뜨는 page sheet, 아이폰에서는 아래에서 올라오는 시트가 된다. `formSheet`는 쓰지 않는다 — react-native-screens 4.26부터 form sheet의 크기·위치를 네이티브 쪽 동기 갱신으로 정하는데, iPadOS에서 시트는 뜨고 **내용이 비어 흰 화면**으로 보였다.

모달 화면에서 `insets.top`을 더하지 않는다. iOS의 `modal`·`formSheet`는 이미 상태 표시줄 아래에서 시작하는데 `useSafeAreaInsets()`는 **시트가 아니라 창 전체**의 인셋을 돌려주므로, 더하면 그만큼 위가 비고 내용이 아래로 밀린다. 전체 화면으로 뜨는 Android 모달에서만 필요하다.

누를 수 있는 것은 `TouchableOpacity`가 아니라 `components/common/PressableScale`로 만든다. 이유는 아래 [조작감](#조작감)에 있다. 예외는 `ErrorBoundary`와 DB를 못 열었을 때의 '다시 시도' 두 곳이다 — 앱이 망가졌을 때 뜨는 화면이라 가장 단순한 부품만 쓴다.

## 조작감

**아이패드에는 진동 모터가 없다.** 햅틱을 불러도 아무 일도 일어나지 않는다. 그래서 '눌렸다'는 확인은 전부 화면의 움직임이 맡는다. 규칙은 하나다 — **누른 순간 바로 들어가고, 손을 떼면 살짝 튕기며 돌아온다.**

### 누름

`PressableScale`이 `TouchableOpacity`를 대신한다. 그쪽은 흐려지기만 해서 화면이 손가락에 답하는 느낌이 없다.

| | 스프링 | 감쇠비 ζ | 느낌 |
|---|---|---|---|
| 누를 때 | stiffness 700 · damping 42 | ≈0.79 | 빠르고 거의 넘치지 않음 — 손가락을 바로 따라온다 |
| 뗄 때 | stiffness 320 · damping 16 | ≈0.45 | 목표를 20% 남짓 넘었다 돌아옴 — '쫀득'한 것은 이 되튐이다 |
| 톡 튀기 | stiffness 260 · damping 13 | ≈0.40 | 자리를 옮긴 카드, 바뀐 숫자 |

되튐까지 딱 멈추면 딱딱하고, 누름까지 출렁이면 흐물거린다. 네이티브 드라이버로 UI 스레드에서 돌아서, 목록을 그리느라 JS가 바쁜 순간에도 끊기지 않는다.

**작은 것일수록 깊게 눌린다.** 같은 비율이면 큰 것이 훨씬 많은 픽셀을 움직이기 때문이다.

| 대상 | 눌림 |
|---|---|
| 원생 카드 | 0.98 |
| 큰 버튼 | 0.96 |
| 작은 버튼(등원 등) | 0.93 |
| 요일 칩 · 하원 · 둥근 버튼 | 0.88 – 0.90 |
| 글자뿐인 동작(결석 · 취소) | 0.88 + 흐려짐 |

### 결과가 보이는 움직임

| 언제 | 무엇이 |
|---|---|
| 등원 · 결석 · 하원 · 취소가 **저장된 뒤** | 그 카드만 한 번 톡 튄다 (0.94 → 1) |
| 〃 | 카드 테두리가 무엇이 됐는지의 색으로 빛났다 꺼진다 — 등원 초록, 하원 파랑, 결석 빨강, 취소 노랑 (0.35초 머물고 0.9초에 걸쳐 꺼짐) |
| 〃 (보드) | 카드가 옮겨 간 칸이 그 카드까지 스크롤한다. 이미 보이면 움직이지 않는다 |
| 칸의 인원이 바뀔 때 (보드) | 떠난 칸과 도착한 칸의 인원 뱃지가 함께 부푼다 (1.25 → 1) |
| 오늘 등원 수 · 요약 숫자가 바뀔 때 | 숫자가 살짝 부푼다 (1.12~1.2 → 1) |
| 다른 탭으로 옮길 때 | 그 탭 아이콘이 톡 튄다 |
| PIN 한 자리 | 점이 톡 튀어나온다 |
| PIN이 틀렸을 때 | 점 줄이 좌우로 고개를 젓는다 |

아이패드에는 진동이 없다. 그래서 결과는 눈으로 확인해야 하고, 튀는 것(0.4초)만으로는 곁눈으로 놓치기 쉬워 **빛**을 더했다. 튀는 것은 '여기로 왔다', 빛은 '무엇이 됐다'를 말한다. 시각 고침은 상태가 바뀐 것이 아니라 튀기만 한다. 빛은 투명도만 바꾸므로 '동작 줄이기'에서도 남긴다.

보드는 칸마다 따로 스크롤하므로, 명단이 길면 방금 등원한 학생이 수업 중 칸 아래 화면 밖에 떨어진다. 빛나고 튀어도 안 보이면 소용이 없어서 그 칸이 카드까지 끌어 준다 (`BoardLane`의 `LaneItem`).

카드는 저장이 **끝난 뒤** 튄다. 누르자마자 움직이면 실패한 날에도 된 것처럼 보인다. 튄 카드는 0.7초 뒤 표시를 지운다 — 남겨 두면 다른 학생을 찍어 목록이 다시 짜일 때 새로 그려지며 또 튄다.

탭 아이콘은 `tabBarIcon`의 `focused`로 판단하지 않는다. 탭바가 아이콘을 두 벌 겹쳐 그리고 투명도만 바꾸는데, 각 벌이 받는 `focused`는 늘 같은 값이라 바뀌는 순간이 없다. 탭바 자신의 상태(`navigation.getState()`)에서 이 탭이 골라졌는지를 본다. `navigation.isFocused()`는 쓰지 않는다 — 위의 스택까지 따져서, 모달이 떠 있는 동안 false가 됐다가 닫힐 때 true로 돌아와 아무도 누르지 않은 탭이 튄다.

### 햅틱 (아이폰에서만)

`utils/haptics.ts`. 결과에 따라 달라지는 것은 결과를 본 뒤에 낸다.

| 종류 | 언제 |
|---|---|
| select | 탭 · 요일 칩 · 세그먼트 · 달·날짜 넘기기 · 켜고 끄기 · 시각 고침 · 보충일 지정 |
| tap | PIN 숫자, 지금 잠그기, 기록 취소, 보충 삭제 |
| success | 등원 · 하원 · 보충 완료 저장, 잠금 해제 |
| warning | 결석 저장 |
| error | PIN 틀림, 저장 실패 |

모든 누름에 붙이지 않는다. 다 떨리면 아무것도 전하지 못한다. 웹은 건너뛴다.

### 손가락이 닿는 자리

아이패드에서 가장 자주 빗나가던 것은 카드 오른쪽의 작은 글자 동작이었다(24pt 남짓). 누를 자리를 키웠고, **`hitSlop`은 옆으로만 넉넉히** 준다. 위아래로 넓히면 쌓여 있는 이웃 동작의 자리를 빼앗는다 — 나중에 그려진 쪽이 이기므로 '하원'을 누르려다 '취소'가 눌린다.

하원은 테두리 있는 알로 바꿨다. 등원 완료 카드에서 가장 자주 누르는 것이고, 바로 아래 '취소'와 모양이 같으면 손이 헷갈린다.

**취소는 한 번 더 묻는다.** 되돌린 뒤 다시 등원을 누르면 그때 시각으로 새로 남아서, 4시에 온 학생을 6시에 잘못 취소하면 도착 시각과 하원 시각을 함께 잃는다.

**저장 실패는 알린다.** 예전에는 카드의 `onPress`가 돌려준 약속을 아무도 받지 않아서, 저장이 안 돼도 화면이 조용했다.

### 동작 줄이기

iOS 설정의 '동작 줄이기'를 켜 두면 튕김·튀기·흔들기를 하지 않는다. 누름은 남긴다 — 눌렸다는 확인까지 없애면 그건 접근성이 아니라 고장이다.

### 하지 않은 것

카드가 '등원 예정'에서 '등원 완료'로 **미끄러지듯 옮겨 가는** 효과(`LayoutAnimation`)는 넣지 않았다. 새 아키텍처에서 가상화 목록과 함께 쓸 때의 동작을 실기기로 확인하지 않고 넣기에는 위험하고, 출석을 찍는 순간에 앱이 멈추는 것은 이 앱에서 가장 나쁜 고장이다. 옮겨 간 카드가 도착한 자리에서 톡 튀는 것으로 대신한다.

## 성능

원생 12명, 아이패드 폭에서 기록 한 번에 원생 카드가 **몇 장 다시 그려지는지** 쟀다.

| | 등원 한 번 | 하원 한 번 |
|---|---|---|
| 전 | 25 | 25 |
| 후 | 7 | 2 |

전에는 오늘 화면 12장에, 뒤에 떠 있는 원생 탭 12장까지 전부 다시 그렸다. 세 가지를 고쳤다.

1. **함수는 늘 같은 것.** `useData`가 데이터가 바뀔 때마다 모든 함수를 새로 만들어서, 그
   함수를 받는 카드가 전부 '바뀐 것'이 됐다. 이제 함수 묶음은 앱이 떠 있는 동안 그대로다.
2. **안 바뀐 행은 예전 객체 그대로.** 쓰기 뒤 DB를 다시 읽으면 모든 행이 새 객체라 카드의
   `React.memo`가 소용없었다. `utils/reconcile`이 `id`와 `updatedAt`이 같은 행은 예전 객체를
   돌려주고, 하나도 안 바뀌었으면 예전 배열 자체를 돌려준다.
3. **행은 자리로 부른다.** 카드 그리드의 행을 첫 학생 id로 불러서, 한 명이 빠질 때마다
   뒤 행들이 통째로 새로 만들어졌다.

남은 7장은 다시 그려야 하는 것들이다 — 옮겨 간 카드, 그리고 한 명이 빠지며 다른 행으로
넘어간 카드들.

그 대가로, 예전에 '함수가 바뀌었다'로 데이터 변경을 알아채던 화면(이력, 일정)은 이제
`revision`을 본다. DB를 다시 읽을 때마다 오르는 숫자다. 날짜를 쓰는 계산은 `today`를 본다
([날짜가 바뀔 때](#날짜가-바뀔-때)).

## 출결 흐름

```
등원 예정 ──[Check In]──▶ 출석 / 예외
        └──[결석]──▶ 결석 기록 + 보충 건 생성
                             │
                   [보충] 탭 ─┴─▶ 날짜 지정 ──▶ 완료
                                              (보충 수업 출결 기록)
```

요일을 옮겨 오는 것은 결석이 아니므로 보충이 아니라 [일정 예외](#일정-예외)로 처리한다.
보충은 실제로 빠진 수업을 나중에 메울 때만 쓴다.

결석과 보충 건은 항상 함께 생성·취소되도록 트랜잭션으로 묶여 있다.
잘못 누른 기록은 카드의 **취소**로 되돌릴 수 있다. 다만 이미 날짜를 잡았거나
완료한 보충은 별도 판단이 들어간 기록이라 취소해도 남는다.

## 요일별 수업 시간

'월 2시, 수 5시'처럼 요일마다 시간이 다른 반이 흔하다. 시간을 하나만 두면 둘 중
하나는 늘 틀린 값이 되고, 등원 판정이 그 값을 그대로 쓰기 때문에 **정상 등원이
조용히 '예외'로 기록된다.**

`students.dayTimes`가 요일별 시간을 담는다. 비어 있으면 모든 요일이
`scheduledStartTime`·`scheduledEndTime`을 쓴다 — 대부분의 원생이 그렇고,
등록 폼도 기본은 시간 한 쌍이다. '요일마다 시간이 다름'을 켰을 때만 요일별 줄이 생긴다.

저장 형식은 `Mon=14:00-16:00|Wed=17:00-19:00` 한 줄이다. `scheduledDays`가 이미
JSON 문자열로 들어가 있어 같은 방식을 따랐다. **기본 시간과 같은 요일은 넣지 않는다** —
저장된 값이 곧 '다른 시간'의 목록이라야, 나중에 기본 시간을 고쳤을 때 낡은 사본이
남지 않는다.

읽는 쪽은 `timesForDay(student, day)` 하나뿐이다. `buildRoster`가 이걸 써서 그 날
시간을 정하고, 등원 판정과 지각 계산이 모두 그 값을 본다.

CSV에도 `dayTimes` 열이 붙는다. 이 열이 없는 옛 파일도 그대로 읽히며, 모든 요일이
기본 시간이 된다.

## 일정 예외

정규 시간표(`students.scheduledDays`)는 매주 똑같이 반복되는 것만 담는다. 그 주에만
달라지는 것은 `schedule_exception` 테이블이 맡는다.

| kind | studentId | 뜻 |
|---|---|---|
| `closure` | 없음 | 그 날 학원 전체 휴강 |
| `extra` | 필수 | 그 날 추가로 오는 원생 (특강, 요일 이동의 도착 쪽) |
| `skip` | 필수 | 그 날 정규 수업에서 빠지는 원생 — **결석이 아니다** |

**요일 이동은 한 쌍으로 표현한다.** 월요일 학생이 화요일에 오면 월요일에 `skip`,
화요일에 `extra`. 결석 기록이 남지 않으므로 출석률이 왜곡되지 않는다.

`extra`에는 `startTime`·`endTime`을 붙일 수 있다. 비우면 원생의 정규 시간을 쓴다.
토요일 특강처럼 시간대가 다른 수업에 쓴다.

명단 계산은 `utils/roster.ts`의 `buildRoster` 한 곳에만 있다. 홈 화면과 일정 화면이
같은 규칙을 봐야 하기 때문이다.

```
휴강이면 → 빈 명단
아니면   → (그 요일 정규 수업자 − skip) + extra
```

휴강은 `extra`보다 우선한다. 문이 닫힌 날에 특강만 남으면 두 예외가 모순되는데,
휴강 쪽이 상위 개념이다.

등원 판정도 이 명단을 쓴다. **오늘 명단에 있고 그 날 적용되는 시간대 안**이면 `scheduled`,
아니면 `unexpected`다. 이전에는 `scheduledDays`만 봐서 특강으로 온 학생이 전부
예외 등원으로 밀렸다.

### 날짜가 바뀔 때

'오늘'은 `refreshData`가 도는 순간에 정해지는데, 그 함수는 쓰기가 일어날 때만 불린다.
학원 문을 닫고 아이패드를 그대로 두면 다음 날 아침에 **어제 명단과 어제 등원 기록이
그대로 떠 있고 오늘 와야 하는 학생은 한 명도 보이지 않는다.**

그래서 `DataProvider`가 두 곳에서 날짜를 확인한다. 포그라운드로 돌아올 때(`AppState`)
한 번, 그리고 화면을 계속 켜 둔 경우를 위해 1분마다. 날짜 문자열이 그대로면 아무 일도
하지 않으므로 비용은 비교 한 번이다.

**화면은 '오늘'을 직접 계산하지 않는다.** `useData()`의 `today`(목록이 읽힌 날짜)를 쓴다.
목록은 바뀌지 않으면 예전 배열을 그대로 쓰기 때문에([성능](#성능)), 원생도 예외도 그대로인
채 날짜만 넘어가면 `new Date()`로 계산하던 명단은 다시 계산되지 않고 **어제 요일의 명단이
남는다.** 실제로 그렇게 깨진 것을 자정 넘김 시험에서 잡았다 — 월요일만 오는 학생이 화요일
아침 명단에 남아 있었다. 날짜를 쓰는 계산은 의존 목록에 `today`를 넣는다.

### 지각·조기 도착

`arrivalOffsetLabel`이 실제 도착과 예정 시작의 차이를 '35분 늦음' 형태로 만든다.
10분 미만은 표시하지 않는다 — 몇 분마다 라벨이 붙으면 눈이 피곤하다.

12시간을 넘는 차이는 반대쪽으로 감아 해석한다. 22:00 시작 수업에 00:30 도착이
단순 뺄셈으로는 '21시간 30분 일찍'이 되기 때문이다.

기록된 시각은 카드에서 눌러 고칠 수 있다. 3시에 온 학생을 5시에 찍으면 5시로
남는데, 그 값이 그대로 이력까지 흘러간다.

## 원생 관리

`StudentFormModal` 하나가 등록과 수정을 겸한다. `studentId` 파라미터가 있으면 수정 모드다.
원생 탭에서 카드를 누르면 수정으로 들어간다.

### 퇴원과 삭제는 다르다

학원에서 사람이 나가는 일은 기록을 없애야 할 일이 아니다. 그래서 폼에는 두 가지가 있다.

| | 명단 | 출결 이력 | 되돌리기 |
|---|---|---|---|
| **퇴원 처리** | 퇴원일부터 빠진다 | **남는다** | 복학 처리 |
| 원생 삭제 | 사라진다 | 함께 사라진다 | 없다 |

그만둔 학생에게 쓰는 것은 퇴원이다. 삭제는 잘못 등록했을 때만 쓴다.

`students.withdrawnAt`에 `YYYY-MM-DD`를 넣는다. 날짜로 판정하는 이유는 이력과 지난
날짜의 일정 화면 때문이다 — 3월에 그만둔 학생이 2월 명단에서까지 사라지면, 다니던
동안의 기록을 다시 볼 방법이 없다. `buildRoster`가 `withdrawnAt <= 그 날짜`인 원생을
건너뛰고, 원생 화면은 **재원 / 퇴원** 두 탭으로 접어 둔다.

퇴원생도 `listStudents`에는 남는다. 여기서 빼면 이력 화면이 id를 이름에 붙이지 못해
그 학생의 출결이 통째로 사라진다. 대기 중인 보충은 보충 탭에서만 감춘다 — 그만둔
학생에게 해 줄 수 있는 보충은 없고, 복학하면 다시 나온다.

원생 정보 수정은 `withdrawnAt`을 건드리지 않는다. 폼이 들고 있는 값으로 같이 쓰면
퇴원생의 수업 시간을 고치는 것만으로 조용히 복학 처리가 된다.

### 동명이인

이 앱에는 학번 같은 외부 식별자가 없다. 화면에 뜨는 것은 이름과 학년뿐이라 김민준이
둘이면 어느 쪽에 등원을 찍는지 알 수 없고, **잘못 찍어도 아무 표시가 나지 않는다.**

`students.note`가 그 자리를 메운다. '월수반', '강북초' 같은 한 마디를 적으면 이름이
나오는 곳마다 학년 옆에 함께 나온다(`studentSubtitle`). 겹치는 이름이 있는데 구분이
비어 있으면 카드가 **이름 겹침 — 구분 필요**를 띄우고, 저장할 때도 한 번 알린다.

CSV 가져오기의 중복 판정은 **이름 + 학년 + 구분**이다. 이름만 보면 두 번째 김민준이
영영 들어오지 않는데, 조용히 건너뛰므로 빠졌다는 사실조차 모른다.

### 삭제가 하는 일

삭제는 출결 기록과 보충 건을 **함께 지운다.** `attendance`와 `makeup`이 `students`를
참조하는데 `ON DELETE CASCADE`가 없고 `PRAGMA foreign_keys`가 켜져 있어서,
자식 행을 먼저 지우지 않으면 기록이 하나라도 있는 원생은 제약 위반으로 삭제가 실패한다.
세 삭제는 한 트랜잭션으로 묶여 있다.

## 하원과 조퇴

등원만 남기면 '몇 시에 갔느냐'는 물음에 답할 수 없다. 조퇴는 그 물음이 실제로 오는
자리다 — 아이를 일찍 데려간 날 부모가 확인을 요청한다.

등원 완료 카드에 **하원** 버튼이 붙는다. 누르면 그 시각이 `attendance.leaveTime`에
남고, 등원 시각과 마찬가지로 눌러서 고칠 수 있다. 예정 종료보다 10분 이상 이르면
`조퇴 · 40분 일찍`이 함께 뜬다(`departureOffsetLabel`). 늦게 간 쪽은 `30분 더 있음`으로,
조퇴를 붙이지 않는다.

결석 행에는 붙지 않는다. 오지 않은 학생이 몇 시에 갔는지는 없는 값이고, 남으면
이력에서 조퇴처럼 읽힌다. SQL 자체가 `status != 'absent'`로 막는다.

## 수납과 신고 자료

받은 수강료를 한 건씩 적고, 그 기록으로 홈택스 신고에 옮길 숫자를 만든다.

원생의 '월 수강료'는 받기로 한 돈이고, 수납 기록은 **실제로 받은 돈**이다. 세금 신고에는
받은 돈만 들어간다. 할인, 분납, 미납, 환불이 있으면 둘은 다르다.

### [수납] 탭

- 달마다 원생별로 **미납 · 일부 · 완납 · 금액 미정**을 보여 준다. 안 낸 사람이 위에 온다.
- 달은 **어느 달 수강료인가**(수강월)이다. 받은 날이 아니다. 10월분을 9월 말에 받아도
  10월에 완납으로 보인다.
- [받음]의 기본값은 오늘, 남은 수강료, **그 집이 지난번에 수강료를 낸 방법**(처음이면 카드)이다.
  대부분 [저장] 한 번이면 끝난다. 앱 전체에서 마지막으로 쓴 방법을 기본값으로 두면,
  방금 다른 집에서 현금을 받은 탓에 카드로 내는 집이 현금으로 잘못 적힌다.
- **무슨 돈인가**(수강료 · 특강비 · 입학금 · 교재대 · 모의고사비 · 기타수입)를 고른다.
  수강료만 완납 판정에 들어간다. 교재비를 받았다고 수강료가 완납으로 보이면 안 된다.
- 계좌이체·현금은 **현금영수증 발급 여부**를 적는다. 10만 원 이상이면 기본으로 켜지고,
  끄면 경고가 뜬다. 학원은 현금영수증 의무발행업종이라 10만 원 이상을 현금(이체 포함)으로
  받으면 요청이 없어도 발급해야 한다 (미발급 금액의 20% 가산세).
- 돌려준 돈은 지우지 말고 **[환불]**로 적는다. 음수로 저장되어 그 달 받은 돈과 신고
  수입금액에서 빠진다. 지우기는 잘못 적었을 때만 쓴다.
- 원생을 삭제해도 수납 기록은 **남는다**. 받은 돈은 이미 일어난 일이고 그 해 신고에
  들어가야 한다.

### 신고용 자료 ([설정] 탭 → 신고용 자료)

연도는 **받은 날** 기준이다. 12월 말에 받은 1월분은 그 해 수입이다.
홈택스에 자동으로 제출하지는 않는다. 숫자를 옮겨 적거나 세무사에게 넘긴다.

| 파일 | 어디에 쓰나 | 담긴 것 |
|---|---|---|
| 사업장현황신고 수입금액 | 사업장현황신고 (2월 10일까지, 학원은 면세사업자) | 수입금액 합계와 구성: 계산서(0, 직접) · 신용카드 · 현금영수증 · 기타. 월별 표. 현금영수증 없는 10만 원 이상 건수 |
| 학원사업자 수입금액검토표 | 사업장현황신고 때 **함께 내야 하는** 서류 (소득세법 시행규칙 별지 제19호의5서식) | 총수입금액 명세(수강료·특강비·입학금·교재대·모의고사비·기타수입), 교습현황(수강단가별 수강연인원·총수강료) |
| 수납 장부 | 종합소득세(5월)의 수입 근거, 세무사 전달용 | 받은 돈 한 건씩 |
| 미취학 아동 교육비 | 보호자가 요청하는 교육비납입증명서 | 원생별 한 해 합계 + 납입일·금액 한 줄씩 |

- **두 서류의 합계는 같아야 한다.** 검토표의 합계는 사업장현황신고서의 수입금액 합계와
  일치해야 하는데, 둘 다 같은 수납 기록에서 나오므로 같다 (`tests/tax.test.mts`가 확인한다).
- **교습현황의 수강연인원**은 '매월 실제 수강인원의 합계'다. (원생, 수강월)마다 받은
  수강료를 더해 그 달의 단가로 보고, 같은 단가끼리 센다. 분납은 합쳐서 한 사람·한 달이다.
  그래서 할인했거나 아직 덜 받은 달은 따로 단가 줄이 생긴다 — 신고 전에 그 줄을 확인한다.
  전부 돌려준 달은 인원에서 뺀다.
- **수납 기록에 없는 칸은 직접 채운다.** 검토표의 과목명·개강횟수·정원, 직원현황, 시설,
  주요 경비. 사업장현황신고서의 시설·임차료·인건비. 계산서를 발행했거나 고용보험 지원금을
  받았다면 그 금액도.
- **미취학 아동**: 초등학교 입학 전 아이의 학원비는 보호자가 교육비 세액공제를 받는데
  연말정산 간소화에 나오지 않아 학원이 교육비납입증명서를 써 준다. 원생 정보의
  '미취학 아동'을 켜 두면, 수납을 기록하는 **그 순간의 값**이 그 건에 찍힌다. 3월에
  입학해 꺼도 1·2월분은 그대로 자료에 남는다.
- 주민등록번호·주소 칸은 비워서 내보낸다. 이 앱은 그런 정보를 받지도 담지도 않는다.

세법과 서식은 해마다 바뀐다. 실제 신고 전에 홈택스 안내나 세무사에게 한 번 확인한다.

### 동기화·백업

수납도 기기 간 동기화와 전체 백업에 담긴다. 수납 기능 전의 백업 파일과, 아직 앱을 올리지
않은 기기의 동기화 파일에는 수납이 없는데, 그런 파일은 '수납 0건'으로 읽는다. 그래서 파일
형식 버전을 올리지 않았다 — 올리면 옛 앱이 새 파일을, 새 앱이 옛 백업을 통째로 건너뛴다.

## 설정 탭

예전에는 [원생] 탭의 톱니바퀴로 여는 시트였다. 학원 정보·수강료 기준·신고 자료·백업처럼
원생과 상관없는 것이 늘어 탭으로 뺐다. 위에서부터 자주 손대는 순서다.

### 학원 정보

상호, 대표자, 사업자등록번호, 전화번호, 소재지, 교육 내용. 교육비 납입 증명서의 학원 칸으로
들어간다. 사업자등록번호는 숫자 10자리로 적으면 저장할 때 `000-00-00000`으로 맞춘다.

### 수강료 기준 · 수업 시간

한 줄에 '주 몇 회 · 몇~몇 학년 → 월 얼마'. 빈 칸은 따지지 않는다. 여러 줄이 맞으면 **조건을
더 많이 채운 줄**이 이긴다 — '1~3학년 25만'과 '4학년 이상 40만'에 '4학년 이상 주 2회 30만'을
더하면 5학년 주 2회는 30만이다 (`utils/fees`, `tests/fees.test.mts`).

- 학년은 원생의 학년 글자에서 숫자를 읽는다. '초3'·'3'·'3학년' → 3, '중1' → 7, '고1' → 10.
  '7세'는 학년이 아니라서 학년 조건이 있는 줄에는 맞지 않는다.
- 원생 등록 화면에서 학년과 요일을 고르면 월 수강료가 **채워진다**. 사람이 금액을 직접 고치면
  그 뒤로는 건드리지 않는다. 이미 수강료가 적힌 원생을 고칠 때도 바꾸지 않고, 기준과 다르면
  '지금 적힌 금액과 다름'이라고만 알린다 — 형제 할인처럼 일부러 다르게 적은 금액이 있다.
- **[수강료가 빈 원생에게 적용]**은 명단을 한꺼번에 가져온 뒤에 쓴다. 비어 있는 재원생에게만
  채우고, 이미 적힌 금액과 퇴원생은 그대로 둔다.
- **기본 수업 시간(분)**은 새 원생의 끝나는 시각을 '시작 + 이 시간'으로 채운다. 끝나는 시각을
  직접 고르면 멈춘다. 비우면 60분.

학원 정보와 수강료 기준은 같은 한 줄(`academy` 테이블)에 담긴다. 두 칸을 따로 저장하므로
늘 **고친 칸만** 지금 저장된 값 위에 얹는다(`patchAcademy`). 각자 들고 있던 옛 값으로 통째로
쓰면 서로 고친 것을 덮는다. 동기화·백업에도 담기며, 두 기기에서 고치면 나중에 고친 쪽이 남는다.

## 교육비 납입 증명서

**인쇄 · PDF로 저장**을 누르면 iPad 인쇄 화면이 열린다. 거기서 프린터로 보내거나, 공유 버튼
(또는 미리보기를 두 손가락으로 벌리기)으로 PDF로 저장해 보호자에게 보낸다.

  전화번호·교육 내용), 납입 내역(납입일·수강월·구분·금액), 합계, 발급일, 대표 (인).

  이 앱은 그런 정보를 받지도 담지도 않는다.
- 인쇄는 `expo-print`다. 네이티브 모듈이라 처음 들어온 버전에서는 `npm run check:native`로
  미리 컴파일된 모듈이 코어와 맞는지 확인했다. 웹 미리보기의 expo-print는 넘긴 HTML이 아니라
  지금 화면을 인쇄해서, 웹에서는 새 창에 증명서를 써서 인쇄한다 (`utils/print`).

## 앱 잠금

수업용으로도 쓰는 아이패드라 아이들이 만질 수 있다. 원생 이름·학년·수강료가 한
화면에 있으므로 화면 앞을 막는다.

**DB를 암호화하지는 않는다.** 막으려는 것이 침입자가 아니라 호기심이고, 암호화는
키를 잃는 순간 기록도 함께 잃는 위험을 새로 만든다 — 이 앱에는 서버가 없다.

PIN은 소금과 함께 SHA-256으로 해싱해 키체인(`expo-secure-store`)에 둔다. 평문은
어디에도 남지 않고, 소금이 기기마다 달라 같은 PIN이라도 저장값이 다르다.
소금 길이를 앞에 붙이는 이유는 `salt:pin` 만으로는 경계가 모호해서다 — 소금이
`x:123`이고 PIN이 `4`인 경우와 소금이 `x`이고 PIN이 `123:4`인 경우가 같은 값이 된다.

Face ID·Touch ID가 먼저 뜨고 PIN은 그것이 안 될 때를 위한 것이다.
**기기 암호 대체를 막지 않는다** — 얼굴 인식이 실패하고 PIN까지 잊으면 기록이
그것으로 끝이기 때문이다.

### 언제 잠기는가

| | |
|---|---|
| 앱을 새로 열 때 | 항상 |
| 백그라운드에 30초 넘게 있다 돌아올 때 | 자동 |
| [오늘] 화면의 자물쇠 | 직접 |

**손으로 잠갔을 때는 Face ID를 자동으로 띄우지 않는다.** 띄우면 화면 앞에 있던
원장선생님 얼굴로 그대로 열려서, 건네주기 직전에 잠근 의미가 사라진다.

잠금 화면은 `Modal`로 올린다. 절대 위치 View로는 부족하다 — 원생 등록·설정·일정은
native-stack이 별도 UIViewController로 띄우기 때문에, 리액트 루트에 형제로 놓인
화면은 그 시트 **아래**에 깔린다. 폼을 열어 둔 채로 자동 잠금이 걸리면 이름·학년·
수강료가 그대로 보이고 수정까지 된다.

시작 게이트가 잠금 확인까지 기다린다. `locked`는 false로 시작하므로, 키체인 읽기가
DB·글꼴보다 늦게 끝나면 잠긴 기기에서도 명단이 한 번 비친다.

자물쇠 버튼이 필요한 이유: **앱을 켠 채로 아이패드를 건네주면 자동 잠금이 걸리지
않는다.** 실제로 그 경우가 가장 흔하다.

30초 유예는 설정 앱을 잠깐 다녀오는 것만으로 매번 다시 풀어야 하는 일을 막는다.

키체인이 없는 플랫폼(웹)에서는 켤 수 있는 것처럼 보여 놓고 조용히 실패하는 대신
쓸 수 없다고 말한다.

## 백업

[설정] 탭에 있다. 기기 밖으로 데이터를 꺼내는 유일한 경로다.

### 전체 백업 — 되돌릴 수 있는 쪽

기록 전부를 JSON 파일 하나로 쓰고, 그 파일로 되돌린다. 기기를 바꾸거나 앱을 지웠을
때 쓰는 것은 이쪽이다.

형식은 [기기 간 동기화](#기기-간-동기화)가 쓰는 스냅샷과 같다. 그래서 복원이
덮어쓰기가 아니라 **병합**이 된다:

- 백업 이후에 찍은 기록은 살아남는다 (지난주 백업을 복원해도 오늘 출결이 안 지워진다)
- 같은 파일을 두 번 복원해도 두 배가 되지 않는다
- 삭제한 원생이 옛 백업으로 되살아나지 않는다 — 묘비가 같이 담긴다

엉뚱한 파일을 고르면 조용히 넘어가지 않고 왜 안 되는지 말한다.

### CSV — 눈으로 보는 쪽

원생 명단 / 출결 기록(전체) / 보충 기록 / 일정 변경을 각각 CSV로 쓴다. 앞에 BOM을
붙여 엑셀에서 한글이 깨지지 않는다.

**이쪽은 되돌릴 수 없다.** 사람이 읽는 형식이라 id도 관계도 없어서, 출결을 어느
원생의 것으로 붙일지 알 수 없다. 가져오기가 원생 명단에만 있는 이유이고, 복구용으로
쓰면 안 되는 이유다.

원생 명단 가져오기는 이름이 같으면 건너뛰므로 같은 파일을 두 번 가져와도 명단이
복제되지 않는다.

내보내기용 전체 이력은 `loadAllAttendance`로 그때그때 읽고 **상태에 담지 않는다.**
담는 순간 오늘로 범위를 좁혀 둔 이유가 사라진다.

CSV 파일은 캐시 디렉터리에 쓴다. 사용자가 공유 시트에서 보관할 곳을 고르고 나면
앱 안의 사본은 쓸모가 없는데, `document`에 두면 지우는 사람이 없어 계속 쌓인다.

## 출결 이력

네 번째 탭. 한 번에 한 달만 보여주고 그 달만 `loadAttendanceRange`로 읽는다.
전체를 상태에 올리지 않는 원칙은 여기서도 같다.

- **학생별** — 원생마다 출석·예외·결석·보충 횟수. 월계표를 만들 때 쓰는 값이다.
- **날짜별** — 날짜로 묶은 상세 기록. "지난주 화요일에 누가 왔더라"를 확인하는 용도.

다음 달 버튼은 이번 달에서 비활성이다. 미래 기록은 존재할 수 없다.
탭에 들어올 때마다 `useFocusEffect`로 다시 읽는다 — 다른 탭에서 체크인하고
돌아왔을 때 옛 숫자가 남아 있으면 안 된다.

## 기기 간 동기화

아이폰과 아이패드에서 같은 출결을 본다. **유료 Apple Developer 계정이 있을 때만
빌드에 포함된다** — iCloud 권한은 무료 Apple ID로 발급되지 않는다.

```bash
npx expo prebuild --clean                       # 동기화 없음 (무료 계정)
EXPO_ICLOUD_SYNC=1 npx expo prebuild --clean    # 동기화 포함 (유료 계정)
```

기본이 꺼짐인 이유: entitlement가 붙은 채로 무료 계정 빌드를 하면 코드 서명에서
실패한다. 동기화 하나 때문에 앱 전체를 설치하지 못하게 만들 수는 없다.
**동기화를 빼도 나머지 기능은 전부 그대로 동작한다.**

앱이 동기화를 시도할지는 **권한 파일**이 정한다. `app.config.js`가 `ios/*/*.entitlements`에
iCloud 컨테이너가 있는지 보고 `extra.icloudSync`로 앱에 심는다. 동기화 라이브러리 자체는
무료 빌드에도 들어가서, 모듈이 있는지로 판단하던 예전에는 무료 빌드에서 'iCloud에
로그인하세요'라고 엉뚱하게 안내하거나, 매번 올리다 실패해 오늘 화면에 '못 맞춤'을 띄웠다.
환경 변수만 보지 않는 이유는 이 설정이 빌드할 때마다 다시 읽히기 때문이다 — 매 빌드마다
변수를 붙이라고 하면 한 번 잊는 순간 동기화가 조용히 꺼진다.

### DB 파일을 통째로 올리지 않는다

가장 쉬운 방법은 `attendance.db`를 iCloud Drive에 두는 것인데, iCloud는 파일 단위로
덮어쓴다. 아이패드 업로드가 끝나기 전에 아이폰을 열면 아이폰은 낡은 파일 위에
기록하고, 충돌 해결에서 **하루치 출결이 통째로 사라진다.**

대신 기기마다 자기 파일에만 쓴다. 두 기기가 같은 파일을 건드리지 않으므로 쓰기
충돌이 구조적으로 생기지 않는다.

```
iCloud/출석부/
  device-<기기id>.json      각 기기가 자기 것만 쓰고, 읽을 때는 전부 읽는다
```

### 무엇이 같으면 같은 기록인가

| 테이블 | 병합 키 |
|---|---|
| 원생 | `id` |
| 출결 | `studentId + date + type` |
| 보충 | `id` |
| 일정 예외 | `date + kind + studentId` |

출결만 `id`가 아니다. 두 기기에서 같은 학생의 같은 날 등원을 각각 찍으면 `id`는
다르지만 같은 사실이라, `id`로 합치면 한 학생이 하루에 두 번 등원한 것처럼 남는다.

정규 등원과 보충도 다르다. 보충 출결의 `id`는 그 보충 건의 `id`를 그대로 쓴다. 같은
날 두 타임을 몰아 보충하는 일이 있어서 학생과 날짜로 묶으면 두 수업이 하나로 뭉개지고,
진 쪽은 지워져 되돌릴 수 없다.

겹치면 `updatedAt`이 늦은 쪽이 이긴다. 시각까지 같으면 `id`로 가른다 — 어느 쪽이
옳다고 할 근거가 없을 때 두 기기가 서로 다른 답을 내면 영원히 서로를 덮어쓴다.

그래서 `stamp()`는 **반드시 앞서 준 값보다 늦은 값**을 준다. 밀리초 해상도라 한
트랜잭션에서 두 번 부르면 같은 값이 나오기 쉬운데, 묘비와 그 자리를 대신할 새 행이
같은 시각을 달면 절반의 확률로 방금 만든 행이 지고 다음 동기화에서 지워진다.

### 계층

```
화면 ─▶ useData ─▶ data/*        (deletedAt IS NULL로 거른 것만)
                    ▲
        sync/* ─────┘            (묘비까지 전부)
```

행을 객체로 바꾸는 일은 `data/*`에만 있다. 동기화가 사본을 들고 있으면 컬럼이
하나 늘 때 한쪽만 고쳐지고, 그 차이는 두 기기를 맞춘 뒤에야 드러난다.

`utils/id.ts`가 `expo-crypto`를 함수 안에서 부르는 것도 이 때문이다. 최상단에서
부르면 SQL과 병합이 네이티브 모듈에 묶여 React Native 밖에서는 불러올 수조차 없고,
스키마와 병합을 실제 SQLite에 돌려 검증하는 길이 막힌다. 표준 `crypto.randomUUID`가
있으면(브라우저·노드) 그쪽을 먼저 쓰고, 없으면(아이패드의 Hermes) `expo-crypto`로 간다.

### 쓰기는 줄을 선다

expo-sqlite의 `withTransactionAsync`는 BEGIN과 COMMIT 사이에서 await하는 동안 **같은 연결의
다른 질의를 막지 않는다.** 그래서 줄을 세우지 않으면:

- 동기화가 병합 트랜잭션을 연 사이 등원을 누르면, 그 등원이 병합 트랜잭션 **안에서**
  실행된다. 병합이 실패해 되돌려지면 화면에 찍혔던 등원도 사라진다.
- 트랜잭션 둘이 겹치면 나중 것의 BEGIN이 실패하고, 그걸 수습하는 ROLLBACK이 **앞 것의
  작업까지** 되돌린다.

그래서 DB를 바꾸는 일은 전부 `db/queue.ts`의 `exclusive()`를 지난다 — 화면의 쓰기
(`useData`의 `write`), 가져오기·복원, 동기화의 DB 단계. 줄은 **가장 바깥 입구 한 곳**에서만
선다. 줄 안에서 또 줄을 서면 앞사람이 끝나기를 영원히 기다린다. iCloud를 기다리는 동안은
줄 밖이다 — 몇 초씩 막으면 그동안 누른 등원이 전부 밀린다.

동기화가 '여기까지 올렸다'고 적는 시각(`lastSyncAt`)은 **올리기 전에, 줄 안에서** 찍는다.
끝난 뒤에 찍으면 내려받는 몇 초 사이에 찍은 등원이 이미 올린 것으로 잡혀, 다음 쓰기가
생길 때까지 상대 기기로 가지 않는다.

`sync/run.ts`는 iCloud 쪽을 인자로 받는다. 그래야 이런 순서를 노드에서 가짜 iCloud와 실제
SQLite로 돌려 볼 수 있다 (`tests/sync.test.mts`, `tests/queue.test.mts`).

### 삭제는 지우지 않는다

행을 없애면 상대 기기 파일에는 아직 남아 있어 다음 병합에서 되살아난다. `deletedAt`만
찍고 화면 질의가 전부 `deletedAt IS NULL`로 거른다. **`src/data`에 `DELETE FROM`은
하나도 없다** (동기화가 병합에서 진 중복 행을 걷어낼 때만 예외다).

### 언제 주고받는가

앱이 포그라운드로 올 때, 쓰기가 잠잠해진 뒤 3초, 백그라운드로 갈 때, 그리고 수동 버튼.
`inactive`는 제외한다 — 공유 시트·제어 센터·앱 전환기가 모두 그 상태를 거치는데 앱을
떠난 것이 아니다. 여기에 반응하면 CSV 한 번 내보낼 때마다 DB 전체를 올린다.

같은 순간에 두 번 돌지 않도록 `runSync`가 진행 중인 약속을 재사용한다. 지난번 이후
이 기기에서 바뀐 것이 없으면 올리지도 않는다.

어느 단계에서 실패하든 로컬 기록은 이미 안전하다 — 기록은 항상 먼저 기기에 저장되고
전송은 그다음이다.

오늘 화면 오른쪽 위에 마지막으로 맞춘 시각이 뜬다. 조용히 실패하지 않게 하는 게
핵심이다. 동기화를 아예 쓸 수 없는 빌드에서는 그 줄이 나오지 않고, 백업 화면에
사유가 뜬다.

### 알아두어야 할 것

`updatedAt`은 **그 기기의 시계**다. 두 기기 시계가 어긋나면 실제로 나중에 고친 쪽이
질 수 있다. iOS는 시각을 자동으로 맞추므로 보통 초 단위 오차이고, 입력자가 한 명이면
같은 기록을 몇 초 안에 양쪽에서 고칠 일은 없다. 원리적으로 없앨 수는 없다.

데이터는 사용자 본인 iCloud 안에만 머문다. 외부 서버는 없다.

## 아직 없는 기능

- 묘비 정리 — 삭제한 기록이 계속 쌓인다. 원생 50명 규모에서는 문제가 안 되지만
  몇 년 쓰면 오래된 묘비를 걷어내는 손질이 필요하다.
- 계산서 발행, 강사 인건비·원천징수, 임차료 같은 경비 — 신고서의 해당 칸은 직접 채운다.
- 보호자 연락처 — 담을 곳이 없다. 담으면 개인정보 처리방침도 함께 손봐야 한다.
