# 전북 농어촌유학생 명단 정리 도구

도교육청 농어촌유학 담당 업무용. 한 시트에 쌓여 있던 유학생 명단 원데이터를
정규화한 관리용 엑셀 워크북으로 바꾼다.

```bash
pip install openpyxl
python build_workbook.py <원본.xlsx> <출력.xlsx>
```

원본 워크북의 **1번 시트만** 읽는다. 숨김 시트(연도별 명단, 정보공개 등)는
과거 산출물이라 건드리지 않는다.

## 왜 나눴나

원본은 1행이 '한 번의 신청'인데, 그 안에 세 가지가 섞여 있었다.

| 섞여 있던 것 | 예 |
|---|---|
| 사람에 관한 정보 | 성명, 성별, 보호자, 원 소속교 |
| 그 회차의 심사 결과 | 배정 희망서, 참가 신청서, 최종 배정, 미선정 사유 |
| 여러 해에 걸친 유학 이력 | 유학 학년도 `2024, 2025, 2026`, 시작일, 종료일 |

세 번째가 한 칸에 뭉쳐 있어서 "2025학년도 1학기 몇 명"을 세려면 학년도 칸을
검색하고 접수일로 2학기를 손으로 빼내야 했다. 그래서 셋을 따로 뗐다.

- `학생현황` — 1행 = 학생. 총괄 시트다
- `신청이력` — 1행 = 원본 1행 (모집 차수별 신청 건). 원본 열을 모두 보존한다
- `유학이력` — 1행 = 학생 × 학기. 집계는 전부 이 표를 센다

## 학생이 거치는 여덟 단계

원본은 결과만 담고 있어서 학생이 지금 어디쯤인지 한눈에 보이지 않았다. 원본
열들이 이미 단계로 나뉘어 있으니 그대로 이었다.

`접수` → `가배정`(학교 배정희망서 선정) → `참가신청서 제출`(학부모) →
`최종배정`(도교육청) → `유학중`, 그리고 끝난 상태로 `유학종료` ·
`중도복귀` · `미선정·미전학`.

`학생현황` 시트는 이 단계들을 날짜 칸으로 옆에 늘어놓고, `현재 단계`는 그
칸들을 **뒤에서부터 보는 수식**으로 정한다. 종료일이 있으면 끝난 상태고,
없으면서 시작일이 기준일보다 앞이면 유학중이고, 그렇지 않으면 마지막으로
찍힌 단계다. 칸을 채우면 단계가 따라 바뀐다 — 단계를 따로 입력하지 않는다.

`종료 유형`도 수식이다. 종료일이 그 학기 마지막 날 이후면 `유학종료`,
학기 도중이면 `중도복귀`.

기준일은 `설정` 시트에 있다. 2026학년도 2학기 배정자처럼 시작일이 아직
오지 않은 학생은 `유학중`이 아니라 `최종배정`에 머문다.

단계 칸이 처음부터 있었던 것은 아니다. 학교 배정희망서·참가신청서 칸은
2025학년도 2학기 모집부터 기록되기 시작했고, 그 전 학기는 결과만 남아 있다.
`모집단계현황` 시트가 학기마다 이를 표시한다.

## 학기를 어떻게 펼치나

3월 1일 시작이 1학기, 9월 1일 시작이 2학기, 학년도는 3월에 바뀐다.
신청 건의 시작일과 종료일 사이에 걸치는 학기를 모두 만든다.

검산은 원본이 해 준다. 이렇게 펼친 학년도 집합이 원본 '유학 학년도' 칸과
어긋난 건이 하나도 없었다 (유학 학년도가 적혀 있는 배정 건 전부).

## 인원을 세는 두 기준

담당자가 쓰는 숫자가 두 가지다. 어느 쪽인지 모르면 값이 안 맞는다.

- **유학생 수(공식 기준)** — 그 학기에 한 번이라도 유학한 인원. 도교육청 발표
  자료 '연도별 시·군 유학생 수'와 같은 기준이다
- **학기말 재적** — 그 학기 끝까지 남은 인원. 다음 학기로 넘어가는 인원과 같다

학기 중에 그만둔 학생만큼 둘이 벌어진다. 워크북은 두 열을 나란히 낸다.

발표 자료와 맞춰 본 결과다. 합계뿐 아니라 **13개 시군 숫자가 전부** 맞았다.

| 학년도 | 공식 기준 | 발표 자료 | 시군별 |
|---|---|---|---|
| 2022 | 27 | 27 | 전부 일치 |
| 2023 | 85 | 85 | 전부 일치 |
| 2024 | 165 | 165 | 전부 일치 |
| 2025 | 269 | 269 | 전부 일치 |
| 2026 (1학기) | **332** | 333 | 고창만 3 vs 4 |

2026학년도 1학기의 1명 차이는 학교 오보고분이라고 담당자가 확인해 주었다.
발표는 333명으로 나갔고 실제는 332명이다. 이 332명 중 학기말까지 남는 인원은
325명으로, 2026학년도 2학기 시작 인원과 같다.

## 판단이 필요했던 곳

**배정 판정.** `최종배정` 칸이 비어 있는 행이 100건 가까이 된다. 아래 순서로 본다.

0. `종료일` 칸에 `미전학`이 있으면 → 미배정. 최종배정을 받고도 실제로 전학하지
   않은 건이 4건 있다. 이 규칙이 없으면 한 학생이 같은 학기에 두 학교로 잡힌다
1. `종료일` 칸에 `최종배정`이라고만 적힌 7건 → **확인필요**. 실제 전학 여부를
   알 수 없고, 발표 자료의 시군별 숫자에도 빠져 있다. 이 7건을 빼야 2026학년도
   1학기가 시군 단위까지 발표 자료와 맞는다
2. `최종배정`이 `배정`/`최종배정` → 배정
2. `최종배정`이 `X`/`미배정`이거나 사유가 적혀 있으면 → 미배정
3. 비어 있으면 `종료일` 칸을 본다. 날짜나 `현재`가 있으면 → 배정
4. 그래도 안 되면 `배정 희망서`가 `선정` → **확인필요**, 다른 사유 → 미배정

`확인필요`로 남은 26건은 `데이터검증` 시트에 모아 둔다. 사람이 봐야 하는 것을
조용히 한쪽으로 정하지 않기 위해서다.

## 검증 항목을 어디까지 잡을 것인가

빈칸을 전부 잡으면 목록이 길어져 정작 손볼 것이 묻힌다. 기준은 **발표 자료와
숫자가 맞는가**로 둔다. 맞으면 그 빈칸은 넘어가도 되는 것이다.

그래서 `데이터검증` 시트는 맨 위에 발표 자료 대조표를 놓고, 그 아래 목록을
둘로 나눈다.

- **조치 필요** (26건) — 집계 숫자를 움직인다. 배정 결과가 비어 판정할 수 없는
  19건, 최종배정 후 전학 여부를 알 수 없는 7건
- **참고** (55건) — 숫자에 영향이 없다. 동명이인 33건, 원 소속교가 다른 동일인
  14건, 현재 학년 표기 차이 8건

처음에는 종료일이 빈 배정 건 28건도 잡았는데, 전부 2026학년도 2학기 신규
배정이었다. 아직 시작하지 않은 학기라 종료일이 없는 것이 맞다. 지난 학기에
시작한 건만 잡도록 고쳤다.

**거주 유형.** `홈스테이형(2022)→유학센터형(2023)` 같은 값은 학기별로 갈라
2022학년도 행은 홈스테이형, 2023학년도부터는 유학센터형으로 넣는다.

**학년.** 각 학기의 학년은 전입 당시 학년에서 학년도가 바뀐 횟수만큼 올린다.
계산 결과가 원본 '현재 학년'과 다르면 검증 항목으로 남긴다.

**체제비 3년.** 도청 지원은 최대 3년 = 6학기. 시작 학기부터 여섯 번째 학기의
마지막 날이 만료일이다. 원본 메모의 "2023년 3월 시작 → 2026년 2월까지"와 같다.
단가는 워크북의 `설정_지원단가` 시트에 빼 두었다 (2025. 전북 농촌유학 시행 지침 기준).

## 개인정보

원본과 산출물 모두 학생·보호자 이름과 연락처를 담고 있다. **저장소에 커밋하지 않는다.**
스크립트만 버전 관리하고, 워크북은 담당자 PC에 둔다.

## 검증

```bash
python verify_workbook.py <출력.xlsx> <원본.xlsx>
```

워크북에 든 수식 7천여 개를 **직접 계산해서** 값을 확인한다. 계산이 되는지만
보지 않고, 집계 시트가 낸 숫자를 원데이터에서 따로 센 값과 맞춘다.

LibreOffice 로 재계산하는 방법을 먼저 썼으나, 실행 환경에 따라 xlsx 를 아예
열지 못하는 경우가 있었다(`Error: source file could not be loaded` — 셀 세 개짜리
파일에서도 났다). 그래서 `formula_eval.py` 에 필요한 함수만 담은 계산기를 두었다.
COUNTIF, COUNTIFS, SUM, IF, OR, MIN, MAX, INDEX 만 다룬다. 워크북이 그 함수만
쓰기 때문이고, 검증기가 그 밖의 함수를 발견하면 실패로 잡는다.

## 현황판 (HTML)

```bash
python web/build_page.py 농어촌유학생_현황판.html
```

**원본 명단을 계속 원본으로 쓰면서**, 그 파일을 브라우저가 직접 읽는다. 파일을
끌어다 놓으면 그 자리에서 정규화하고 모든 화면을 그린다. 원본을 고친 뒤
'다시 읽기'를 누르면 다시 계산된다. 서버가 없고 바깥으로 요청도 없어서
파일이 이 컴퓨터를 떠나지 않는다.

| 탭 | 하는 일 |
|---|---|
| 요약 | 학생이 지금 어느 단계에 몇 명씩, 학기별 추이, 모집 단계별 이탈, 발표 자료 대조 |
| 교차표 | 세로·가로·값을 골라 표를 만든다. 표 복사 / CSV 내려받기 |
| 학생 | 이름으로 찾고, 신청부터 지금까지를 시간순으로. 체제비 만료 임박 목록 |
| 입력 | 새 학생을 채우면 **원본 시트의 열 차례 그대로** 한 줄을 만들어 준다 |
| 확인 항목 | 손봐야 할 곳. 집계를 움직이는 것과 아닌 것을 갈라 둔다 |

### 교차표

한 칸은 **그 조건에 해당하는 학생 수**이고, 같은 학생이 한 칸 안에서 두 번
세어지지 않는다. 그래서 열을 '학년도'로 두면 1·2학기를 모두 다닌 학생도 한 번만
세어져 발표 자료와 같은 값이 나온다 — 시군까지 그대로 맞는다.

세로는 유학 지역·학교·거주 유형·학년·성별·원 지역·원 소속교·신규계속,
가로는 학년도·학기, 값은 유학생 수·학기말 재적·신규·성별·거주 유형 중에서 고른다.
차례는 인원순·이름순·발표 자료 순서(시군 차례) 중에 고른다.

모집이 진행 중인 학기는 기본으로 뺀다. 켜 두면 2026학년도 열이 1학기 기준 332명이
되어 발표 자료와 맞고, 끄면 진행 중인 2학기까지 더해진다.

### 입력

원본은 그대로 두고 쓴다. 폼을 채우면 원본 30개 열 차례대로 탭으로 구분한 한 줄을
만들어 주고, 복사해서 원본 맨 아랫줄에 붙여넣으면 된다. 고르는 값은 지금 열려 있는
파일에 이미 있는 값에서 뽑으므로 표기가 갈리지 않는다. 접수일 칸의 모집 차수
인코딩(2026-09-02 = 2026학년도 2학기 2차)도 학기·차수를 고르면 자동으로 만든다.
같은 이름·연락처가 이미 있으면 재신청 건이라고 알려 준다. 형제자매처럼 여러 명은
담아 두었다가 한꺼번에 복사한다.

### 원본과 어긋나지 않는지

```bash
python verify_against_source.py <원본.xlsx> <워크북.xlsx>
```

만든 워크북이 원본을 얼마나 충실히 옮겼는지를 셀 단위로 맞춘다. 두 가지를 본다 —
원본의 값이 하나도 빠짐없이 남아 있는가, 그리고 원본에 없는 값을 만들어내지
않았는가.

| 무엇을 | 결과 |
|---|---|
| 원본 741행 ↔ 신청이력 741행 | 한 줄에 한 줄씩 맞물림 (`원본 행` 열로 찾아감) |
| 원본 30개 열 × 741행 = 22,230칸 | 어긋남 0칸, 다듬음 3칸 |
| `원본_전체` 사본 22,470칸 | 어긋남 0칸 |
| 성별·유학지역·거주유형·최종배정 값 분포 | 모두 일치 |
| 유학 학년도 칸 507건 | 어긋남 0건 |

다듬은 3칸은 `'정읍 '` → `'정읍'`, `' '` → 빈칸이다. 이런 것은 '어긋남'이 아니라
'다듬음'으로 따로 세어 무엇을 손댔는지 보이게 한다.

원본 741행이 각각 어디로 갔는지도 함께 낸다 — 배정 535건은 유학이력 1,300행으로
펼쳐지고, 미배정 180건과 확인필요 26건은 신청이력에만 남는다. 합이 741이라 사라진
줄이 없다. 같은 내용이 워크북의 `데이터검증` 시트 맨 위에도 들어간다.

### 파이썬과 같은 답을 내는지

```bash
python verify_web.py <현황판.html> <원본.xlsx>
```

같은 원본을 파이썬과 브라우저 양쪽에 물려 학생 수·단계·학기별·시군별 인원을
맞춘다(73개 항목). 규칙을 한쪽만 고치면 여기서 갈린다.

**시간대마다 돌린다.** 처음에는 UTC 에서만 확인했는데, 한국(UTC+9)에서 열면
숫자가 전부 어긋났다. 엑셀 날짜를 라이브러리가 Date 로 바꿔 줄 때 앞선
시간대에서 하루가 밀려 3월 1일이 2월 28일이 되고, 그러면 1학기가 앞 학년도
2학기로 잡혀 학기가 줄줄이 늘어난다. 2026학년도가 332명에서 360명이 되는 식이다.

그래서 날짜는 Date 로 받지 않는다. 엑셀 일련번호에서 연·월·일만 뽑아 쓴다
(`cellDate()`). 검증기는 서울·UTC·뉴욕·호놀룰루 네 시간대에서 돌려 모두 같은
답이 나오는지 본다.

색은 `dataviz` 규칙을 따랐다. 진행 단계는 파랑 한 색의 4단 ordinal 램프, 끝난
상태는 초록·회색·빨강. 두 계열 꺾은선은 파랑·주황. 팔레트는 검증기를 돌려
밝기 대역·색각 분리·대비를 통과시킨 값이다.
